## 2. 7 天详细计划

### Day 1 · 全景与边界

**阅读**：`01-overview.md`、交互地图“全部”视图。

**动手**：

1. 在图上找出 L1/L2/L3/L4 各 2 个节点；
2. 点开“隐私·留存·审计”“模型发布门禁”“外部集成”，各写 1 条边界；
3. 用一句话解释“为什么应用层多租户 ≠ 数据平台多租户”。

**自测**：

## 3. 综合练习：端到端复盘

### 任务

选择一个真实学生问题，追踪：

1. 登录身份（JWT/租户/角色）；
2. 课程/章节/知识点；
3. RAG 检索到的切片与引用；
4. 回答是否降级；
5. 对话/练习写入哪些表；
6. 事件是否入 Kafka/outbox；
7. 湖表是否更新；
8. 报告/DataOps 是否可见；
9. 涉及哪些隐私/审计记录。

### 输出

一页纸，包含：

- 链路图；
- 每步证据（接口/表/日志/页面）；
- 1 个已验证结论；
- 1 个边界/缺口；
- 1 个改进建议。

### 评分 rubric

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 链路完整 | 缺 3 步以上 | 缺 1–2 步 | 9 步完整 |
| 证据 | 只有描述 | 有文件/接口 | 有运行数据/截图/日志 |
| 边界 | 把外部写成已完成 | 标注但无责任方 | 明确责任方与下一步 |
| 表达 | 难以复述 | 基本清楚 | 10 分钟可讲清 |

## 4. 自测题参考答案（要点）

### 01 全景

1. L1 HodoopForge；L2 EduLake+DataOps；L3 Edumind；L4 问渠智伴。
2. 应用层：`tenant_id` + 租户解析 + 权限 + 双租户测试已上线；数据平台：`tenant_registry`/湖表隔离未上线。
3. 等保测评、Kerberos/TLS/KMS、万人在线、原生 APP、650+ 课单、会议/教务/物流等。
4. 84.8% 是代码/配置/运行证据的技术自检，不是测评机构报告。
5. 浏览器 → WebSocket → Agent/RAG → PG/Kafka → Flink/Iceberg → DataOps → 报告。

### 02 架构

1. PostgreSQL 是事务源，Iceberg 是分析副本，避免双写和事务复杂度。
2. 不会；事件先落 outbox，Kafka best-effort。
3. 见上；数据平台仍需平台窗口。
4. 登录、课程、Agent、Qdrant、PG、Kafka、Flink、Iceberg、Spark、DataOps、报告。
5. 单 GPU、单 app、单 Kafka 等；扩容先做多副本/负载均衡/压测。

### 03 数据平台

1. ODS 贴源、DWD 清洗、DWS 汇总、ADS 应用。
2. 在 DWS/ADS 写入前；报表层检查太晚，坏数据已扩散。
3. 标注覆盖率和未上报作业，不用“100%”掩盖。
4. 对话正文由 PG 日批/CDC 入湖；Kafka 只传元数据。
5. `tenant_registry`/湖表隔离；责任方为数据平台。

### 04 模型

1. 单次波动大；中位数更稳。
2. 明确说“没有找到教材依据”，不编造。
3. P100/P4 的 CTranslate2 不支持 float16。
4. 纠错/润色/查重/公式/口语题/试卷质量；保证 CI/课堂不依赖外网。
5. `dockerfile.gpu` 独立补丁层，保留 ASR/CUDA 缓存层。

### 05 教学应用

1. 保留统计聚合，避免破坏班级/课程统计；同时去除直接标识和自由文本。
2. 2026-11-25 起新写入绑定；历史行只有 `history_uid`，需人工核对。
3. 课堂互动解决即时参与；互动视频解决异步学习中的交互与成绩。
4. 叠加关系：内建角色权限 + 自定义角色权限。
5. 练习提交事件 + `completion_rule`。

### 06 安全合规

1. 自检不是测评；测评需机构、备案、物理/管理证据。
2. 保留聚合数据用于教学统计；直接标识和自由文本已删除/脱敏。
3. 能发现删行/改行/断链；不能发现“从未写入”或外部系统篡改。
4. 应用层已上线；数据平台湖表隔离待。
5. 避免外部通告阻断课堂；补偿控制是 JWT 仅 HS256、ecdsa 不在签名路径。

### 07 运维

1. 源码 bind mount；依赖在镜像内，必须重建。
2. compose 同时带 `docker-compose.yml` + `docker-compose.gpu.yml`，并设置 `WENQU_DEPLOY_COMPOSE_FILES`。
3. 不覆盖生产库，失败不影响线上。
4. 不会；部署包校验/门禁失败会拒绝。
5. 先停写/备份/定位断点，不要直接重写文件。
